# Game Design Document
# «Стройка без иллюзий»

**Версия:** 0.3  
**Жанр:** Idle / Event-driven Business Simulator  
**Платформа:** Android (первая), iOS (вторая очередь)  
**Движок:** Unity 2022 LTS  
**Аудитория:** Мужчины 25–45, СНГ. Строители, инженеры, подрядчики, ИТР, бизнес.  
**Монетизация:** Rewarded Ads + IAP (Premium Currency)  

---

## 1. Executive Summary

«Стройка без иллюзий» — мем-симулятор подрядчика в духе СНГ строительного рынка.  
Игрок начинает как ИП с одной газелью и пытается вырасти до генподрядчика, не сойти с ума и получить хотя бы часть оплаты.

**Ключевое отличие:** реальные боли — КС-2, ПТО, ИД, казначейство, субподрядчики — поданы как контролируемый хаос с чёрным юмором.

**Вирусный потенциал:** каждая игровая ситуация — это готовый TikTok-ролик. Аудитория узнаёт себя и репостит.

---

## 2. Core Philosophy

> **Игрок должен постоянно быть: почти в минусе, почти успевать, почти сдавать объект.**

Это не стройка. Это **симулятор выживания подрядчика**.

### Эмоциональный маятник

| Стресс | → | Облегчение |
|--------|---|-----------|
| Нет денег | | Пришла оплата |
| Косяк на объекте | | Удалось закрыть |
| ПТО вернуло ИД | | КС-2 подписан |
| Бригада ушла | | Нашли новых |
| Кассовый разрыв | | Дали аванс |
| Ростехнадзор пришёл | | Пронесло |

Retention строится на том, что мозг **ждёт разруливания**.

## 3. Core Loop

```
1. Взял объект
2. Посчитал смету
3. Оплатил аванс материалов
4. Нанял/отправил бригаду
5. Строится (idle income)
6. Что-то пошло не так (событие)
7. Решил событие
8. Закрыл этап, сдал ИД
9. КС-2 → подписание
10. ОЖИДАНИЕ ОПЛАТЫ (retention hook)
11. Деньги пришли (облегчение)
12. Масштабируешься → следующий объект
```

### Retention Hook: Оплата через время

Ключевая механика удержания:

```
Объект сдан. КС-2 подписан.
Статус: "КАЗНАЧЕЙСТВО: ОЖИДАНИЕ (3ч 40мин)"
```

Игрок заходит. Проверяет. Возвращается. Удерживается.

**Rewarded Ad:** «Позвонить в бухгалтерию» → -30 минут ожидания.  
**Premium:** «Подключить своего человека» → мгновенная оплата.

## 4. Progression Stages

### Stage 1: ИП «Выживание»
- 1 объект
- 2 рабочих
- Газель  
- Инструмент б/у
- Долг 50 000 ₽
- Объекты: квартиры, ремонты

### Stage 2: Бригада
- 5–8 рабочих
- Прораб нанят
- Снабженец
- ПТО-специалист
- Объекты: офисы, магазины, небольшие склады

### Stage 3: Компания
- Несколько объектов параллельно
- Офис
- ООО оформлено
- Есть юрист
- Первые субподрядчики
- Объекты: ТЦ, склады, промзоны

### Stage 4: Генподряд
- Субчики
- Штрафные санкции
- Кассовые дыры на десятки миллионов
- Государственные заказы
- Казначейство, госэкспертиза
- СРО под угрозой

### Stage 5: Империя
- Сеть объектов
- Техника в собственности
- Участие в тендерах
- «Связи» как ресурс
- Политический уровень

## 5. Systems Design

### 5.1 Система объектов

**Типы объектов:**

| Тип | Сложность | Ценность | Токсичность заказчика |
|-----|-----------|----------|----------------------|
| Квартира | ⭐ | 300–700к | Низкая (обычно) |
| Офис | ⭐⭐ | 1–3М | Средняя |
| Магазин/ТЦ | ⭐⭐⭐ | 3–10М | Высокая |
| Склад/Промка | ⭐⭐ | 2–8М | Средняя |
| Госзаказ | ⭐⭐⭐⭐⭐ | 5–50М | Максимальная (казначейство) |
| Пожарка/Вентиляция | ⭐⭐⭐ | 1–5М | ПТО орёт |
| Серверная | ⭐⭐⭐⭐ | 2–8М | Требования уровня NASA |

**Параметры объекта:**
- `Бюджет` — контрактная стоимость
- `Аванс` — % от бюджета, приходит сразу
- `Срок` — дни до дедлайна
- `Оставшаяся оплата` — задерживается (retention hook)
- `Настроение заказчика` — влияет на итоговый % оплаты
- `ЭвентМультипликатор` — насколько часто что-то идёт не так
- `Сложность ИД` — количество итераций сдачи документов

**Фазы объекта:**
```
Закупка → Строительство → Отделка → Сдача ИД → КС-2 → Ожидание оплаты → Получено
```

### 5.2 Заказчики

**4 архетипа:**

**Нормальный**
- Платит по договору
- Редко меняет ТЗ
- Реальная редкость

**Токсичный**
- Постоянно меняет проект
- Требует бесплатно
- Тянет оплату
- Высокая репутационная награда за терпение

**Госка (государственный заказчик)**
- Самый прибыльный
- Казначейство ест 30–60 дней
- Акты каждый месяц
- Проверки постоянно
- Огромный retention потенциал

**Генподряд**
- Штрафы за опоздание
- Удержания за любой повод
- Переносы дедлайнов без доп.оплаты
- Обвиняет субподрядчика (тебя) во всём

### 5.3 Бригада

**Параметры рабочего:**
- `Скорость` — вклад в прогресс/тик
- `Качество` — снижает шанс переделки
- `Цена` — ежедневный расход
- `Надёжность` — шанс событий (запой, уход)
- `Специализация` — важна для типа объекта

**События с рабочими:**
- «Вася ушёл в запой» — -1 рабочий на N дней
- «Уехали на другой объект» — бригада уходит к конкуренту
- «Требуют аванс досрочно» — кассовый разрыв
- «Сделали косяк» — переделка, потеря прогресса
- «Украли кабель со склада» — прямые потери
- «Травма на объекте» — штрафы + репутация

**Апгрейды бригады:**
- Прораб: координирует, снижает запои
- Снабженец: ускоряет закупки
- ПТО-специалист: снижает кол-во итераций ИД
- Юрист: снижает штрафы

### 5.4 Система ИД (Исполнительная документация)

**Главная мем-механика.**

Игрок собирает пакет документов:
- Акты скрытых работ
- Сертификаты на материалы
- Исполнительные схемы
- Протоколы испытаний
- Фотофиксация

**Сдача ИД — мини-игра:**

```
Вы сдали ИД.
ПТО изучает документы...

[3 секунды]

ВОЗВРАЩЕНО:
"Нет подписи на листе 48"
[Итерация 1 из ?]
```

**Возможные причины возврата:**
- «Нет печати на акте №3»
- «Неправильный шрифт в исполнительной схеме»
- «Не хватает фотофиксации узла Б-4»
- «Дата не совпадает с журналом работ»
- «ПТО требует повторного освидетельствования»
- «Документы потеряны. Просим подать заново.»
- «Подпись не соответствует образцу»

**Количество итераций зависит от:**
- Сложности объекта
- Наличия ПТО-специалиста
- Репутации
- Потраченных «Связей»

**Rewarded ad:** «Позвонить знакомому в ПТО» → принимают с первого раза.

### 5.5 Финансовая система

**Ресурсы:**
- `Касса` — реальные деньги
- `Дебиторка` — ожидаемые оплаты
- `Кредиторка` — долги поставщикам
- `Кассовый разрыв` — момент когда расходы > кассы

**Кассовый разрыв:**
Самый стрессовый момент.
```
Касса: -40 000 ₽
Ожидается: +850 000 ₽ (через 2 дня)
Зарплата бригаде: завтра
```

Решения:
- Взять микрокредит (−% прибыли)
- Договориться с поставщиком об отсрочке
- Попросить аванс у заказчика (−репутация)
- Занять у «связей» (расходует ресурс)

**Расходы:**
- Ежедневные зарплаты бригады
- Закупка материалов (по фазам)
- Штрафы за события
- Налоги (квартальные события)
- Аренда склада/офиса (Stage 2+)

### 5.6 Система «Грязи» (Event System)

Случайные события — сердце игры.

**Категории:**

**Бригада:**
- Запой
- Уход на другой объект
- Требование аванса
- Косяк → переделка
- Травма

**Заказчик:**
- «Хочу передвинуть стену»
- «Добавьте это, это бесплатно же?»
- «Изменилось ТЗ» (после 60% готовности)
- «Пропал» (не отвечает 3 дня)
- «Нашёл нарушения» (попытка не платить)

**ПТО/Документы:**
- Возврат ИД (итерации)
- Требование доп. документов
- Повторное освидетельствование

**Внешние:**
- Ростехнадзор с проверкой
- Пожарная инспекция
- Налоговая
- Прокуратура (редко, сильный удар)
- Кража кабеля
- Ливень → остановка работ
- Мороз → нельзя бетонировать
- Скачок цен на материалы
- Банкротство поставщика
- Субподрядчик пропал с авансом

**LiveOps-события (еженедельные):**
- «Сезон госзаказов» — лучше аванс
- «Проверка Ростехнадзора по региону»
- «Зимняя стройка» — доп. расходы, медленнее
- «Скачок курса доллара» — материалы дороже
- «Дефицит рабочей силы» — зарплаты выше

### 5.7 Система Репутации

**Влияет на:**
- Доступность контрактов (лучшие объекты при высокой репутации)
- Размер аванса (доверие = больше денег вперёд)
- Лояльность ПТО (меньше итераций ИД)
- Скидку на штрафы

**Репутация растёт:**
- Сдача без нарушений дедлайна
- Высокое настроение заказчика при закрытии
- Победа в «судебных» событиях
- Устранение замечаний без скандала

**Репутация падает:**
- Срыв дедлайна
- Уход без доп.соглашения
- Штрафные события (Ростехнадзор)
- Низкое настроение заказчика

### 5.8 Система «Связей»

«Связи» — специальный ресурс. Накапливается медленно.

**Использование:**
- Ускорить согласование (сэкономить дни)
- Провести ИД с первого раза
- Уменьшить штраф от проверки
- Получить тендерную информацию заранее
- Получить аванс у постоянного заказчика вне очереди

**Накопление:**
- Завершение объектов с высоким настроением заказчика
- Победа в «политических» событиях
- Определённые апгрейды (юрист, снабженец со связями)
- Premium purchase

Пример пакетов:
- 50 «связей» — 99 ₽

- Дополнительные события (казначейство)

- После завершения объекта

```

[объект горит]
```

- Хэштеги: #стройка #прораб #строительство #бизнес #симулятор

## 8. Tone of Voice

Игра должна быть **саркастичной, жизненной, «больно смешной»**.

**Вместо:** «Ошибка документации»  
**Писать:** «ПТО снова нашло проблему на листе 48»

**Вместо:** «Задержка платежа»  
**Писать:** «Казначейство ушло думать. Вернётся когда-нибудь.»

**Вместо:** «Рабочий недоступен»  
**Писать:** «Вася недоступен. По данным разведки — на даче у брата.»

**Вместо:** «Инспекция»  
**Писать:** «Пришли люди с папками. Смотрят на Васину каску.»

## 9. Tech Architecture (Unity)

### Стек
- **Unity 2022.3 LTS**
- **TextMeshPro** — UI текст
- **Unity UI (uGUI)** — интерфейс
- **Newtonsoft.Json** — сериализация
- **Unity Ads / IronSource MAX** — реклама
- **Firebase Analytics** — аналитика
- **GameAnalytics** — игровая аналитика

### Архитектура
```
GameManager (Singleton) — главный контроллер
  ├── Systems (MonoBehaviour, DI через Inject)
  │   ├── ProjectSystem
  │   ├── WorkerSystem
  │   ├── FinanceSystem
  │   ├── EventSystem
  │   ├── DocumentSystem
  │   ├── ClientSystem
  │   └── ProgressionSystem
  ├── GameState (POCO, сериализуемый)
  └── UIManager → экраны и попапы

ScriptableObjects — данные (контракты, рабочие, события)
SaveSystem — JSON на диск
AdsManager — обёртка над рекламой
AnalyticsManager — трекинг событий
```

### ScriptableObjects
- `ContractDefinition` — все параметры контракта
- `WorkerDefinition` — параметры рабочего
- `GameEventDefinition` — событие + варианты ответа
- `UpgradeDefinition` — апгрейды компании
- `ClientTypeDefinition` — архетип заказчика
